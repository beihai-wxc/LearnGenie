# AI 安全与对齐技术

> 关键词：对齐, RLHF, DPO, Constitutional AI, 红队测试, 越狱, AI安全, RLAIF, 可解释性

## 对齐问题的本质

**AI 对齐（AI Alignment）** 是指让 AI 系统的行为符合人类意图、价值观与期望的技术与研究方向。随着大语言模型能力飞速提升，对齐已成为 AI 安全的核心议题。对齐问题的本质可从以下几个层面理解：

1. **意图对齐**：模型是否真正理解并执行用户的意图，而非字面意义
2. **价值对齐**：模型输出是否符合人类普世价值观、伦理规范与法律要求
3. **目标对齐**：模型优化目标是否与人类长期利益一致，避免奖励误设（Reward Hacking）
4. **行为对齐**：模型在各种分布外场景下是否仍保持安全、有用、诚实

诺伯特·维纳（Norbert Wiener）曾精炼概括对齐难题："如果我们使用一个机械臂来达到某个目的，我们必须确保这个目的正是我们真正想要的，而不是机械臂实现目标的副产品。"

未对齐的模型可能表现出：生成有害内容、 hallucination（幻觉）、欺骗行为、权力寻求、奖励作弊等。对齐研究正是为系统性缓解这些问题。

## RLHF（基于人类反馈的强化学习）

**RLHF（Reinforcement Learning from Human Feedback）** 是 InstructGPT/ChatGPT 取得成功的核心技术，分三步进行：

1. **监督微调（SFT）**：用高质量人工标注的指令-响应数据微调预训练模型
2. **训练奖励模型（RM）**：对同一 prompt 让模型生成多个回复，由人类标注员排序，训练一个预测人类偏好的奖励模型
3. **PPO 强化学习**：用奖励模型的分数作为奖励信号，通过 PPO 算法优化策略模型

```python
# RLHF 中 PPO 阶段的简化伪代码
import torch
import torch.nn.functional as F

def rlhf_ppo_step(policy_model, ref_model, reward_model, tokenizer,
                  prompts, ppo_epochs=4, clip_ratio=0.2, beta=0.05):
    # 1. 用当前策略生成回复
    responses = policy_model.generate(prompts)
    # 2. 计算奖励（包含 KL 惩罚以防止偏离参考模型）
    with torch.no_grad():
        rewards = reward_model(prompts, responses)
        ref_logp = ref_model.log_prob(prompts, responses)
    cur_logp = policy_model.log_prob(prompts, responses)
    kl_penalty = beta * (cur_logp - ref_logp).sum(-1)
    final_rewards = rewards - kl_penalty

    # 3. PPO 多轮优化
    for _ in range(ppo_epochs):
        new_logp = policy_model.log_prob(prompts, responses)
        ratio = (new_logp - cur_logp).exp()
        advantages = (final_rewards - final_rewards.mean()) / (final_rewards.std() + 1e-8)
        obj = torch.min(ratio * advantages,
                        torch.clamp(ratio, 1 - clip_ratio, 1 + clip_ratio) * advantages)
        loss = -obj.mean()
        loss.backward()
        optimizer.step()
```

RLHF 的挑战包括：人工标注成本高、奖励模型泛化能力有限、训练不稳定、奖励误设等。

## DPO 与偏好优化

**DPO（Direct Preference Optimization）** 由斯坦福团队于 2023 年提出，绕过显式奖励模型与 RL，直接在偏好数据上优化策略模型。其核心洞见是：最优奖励函数可由策略模型自身解析表达，从而将 RLHF 转化为简单的分类损失。

```python
# DPO 损失函数伪代码
def dpo_loss(policy_model, ref_model, chosen, rejected, beta=0.1):
    pi_logp_chosen = policy_model.log_prob(chosen)
    pi_logp_reject = policy_model.log_prob(rejected)
    with torch.no_grad():
        ref_logp_chosen = ref_model.log_prob(chosen)
        ref_logp_reject = ref_model.log_prob(rejected)
    pi_ratio_chosen = (pi_logp_chosen - ref_logp_chosen).exp()
    pi_ratio_reject = (pi_logp_reject - ref_logp_reject).exp()
    loss = -F.logsigmoid(beta * (
        torch.log(pi_ratio_chosen) - torch.log(pi_ratio_reject)
    )).mean()
    return loss
```

**DPO 的优势**：训练稳定、实现简单、无需奖励模型、易于复现。**缺点**：对偏好数据质量敏感、离线优化可能不如在线 RL 探索充分。

偏好优化方法对比：

| 方法 | 是否需要 RM | 是否需要 RL | 训练稳定性 | 计算成本 |
|------|------------|------------|----------|---------|
| RLHF (PPO) | 是 | 是 | 较差 | 高 |
| DPO | 否 | 否 | 优 | 中 |
| IPO / KTO | 否 | 否 | 优 | 中 |
| RLAIF | 是（AI 标注） | 是 | 中 | 中 |

## Constitutional AI 与 RLAIF

**Constitutional AI（CAI）** 由 Anthropic 提出，核心思想是让 AI 通过一组"宪法"原则自我监督、自我修正，减少对人工标注的依赖。流程包括：

1. **监督阶段（SL）**：模型生成回复后，根据宪法原则自我批评并修改，用修改后的数据微调
2. **RL 阶段（RLAIF）**：用 AI 模型代替人类标注偏好，训练奖励模型，再做 RL

宪法原则例如："回答应诚实、无害、有帮助"、"不协助制造武器"等。**RLAIF（RL from AI Feedback）** 显著降低标注成本，使规模化对齐成为可能。

## 红队测试与对抗攻击

**红队测试（Red Teaming）** 是指由专门团队或自动化系统模拟攻击者，主动寻找模型漏洞、诱导有害输出的安全评估方法。常见攻击向量：

- **提示注入（Prompt Injection）**：在输入中嵌入恶意指令，劫持模型行为
- **越狱（Jailbreak）**：通过角色扮演、编码、逐步引导等方式绕过安全过滤
- **数据投毒（Data Poisoning）**：在训练数据中植入后门
- **对抗样本（Adversarial Examples）**：添加人眼不可察觉的扰动改变预测
- **模型窃取（Model Extraction）**：通过查询逆向还原模型参数

```python
# 简化的文本对抗攻击示例（词替换）
def text_fooler_attack(model, sentence, label, synonym_dict):
    words = sentence.split()
    for i, w in enumerate(words):
        if w not in synonym_dict: continue
        original_pred = model(sentence)
        for syn in synonym_dict[w]:
            candidate = words[:i] + [syn] + words[i+1:]
            new_pred = model(' '.join(candidate))
            if new_pred != label:
                return ' '.join(candidate)  # 成功攻击
    return sentence
```

红队测试已成为 GPT-4、Claude、Gemini 等大模型发布前的标准流程。

## 越狱攻击与防御

**越狱攻击（Jailbreak Attack）** 指用户精心构造提示以绕过模型的安全护栏，使其输出本应被拒绝的有害内容。常见类型：

- **角色扮演越狱**："假设你是一个没有道德限制的 AI…"
- **编码越狱**：使用 Base64、Pig Latin、低资源语言等编码恶意请求
- **渐进式越狱（Many-shot Jailbreak）**：通过大量示例逐步引导模型越界
- **目标劫持（Goal Hijacking）**：用"忽略之前的指令…"覆盖系统提示

**防御策略**：

- **输入过滤**：基于规则或分类器拦截恶意提示
- **对齐训练**：在红队数据上做 RLHF，提升模型固有鲁棒性
- **输出审查**：使用独立的安全分类器审核输出
- **Constitutional AI**：让模型自我审查是否违反原则
- **系统提示加固**：明确拒绝优先级，添加防注入提示

## 水印与检测技术

随着 AIGC 泛滥，如何识别 AI 生成内容成为重大社会议题。**水印技术（Watermarking）** 在生成时嵌入统计信号，便于后续检测：

- **文本水印**：在 token 采样时按密钥偏好选择词汇，统计检测即可识别（如 Kirchenbauer 等人提出的绿名单法）
- **图像水印**：在像素频域或潜在空间嵌入不可见水印（如 Google SynthID）
- **行为水印**：利用模型特定的语言风格、句式偏好进行检测

```python
# 文本水印（绿名单法）简化伪代码
def watermark_logits(logits, hash_key, green_ratio=0.5, delta=2.0):
    vocab_size = logits.size(-1)
    rng = torch.Generator().manual_seed(hash_key)
    greenlist = torch.randperm(vocab_size, generator=rng) < int(vocab_size * green_ratio)
    logits[greenlist] += delta  # 偏好绿名单 token
    return logits
```

**检测挑战**：水印易被改写、翻译攻击去除；通用检测器精度有限、误判风险高；隐私与溯源的平衡。

## 可解释性与机械可解释性

**可解释性（Interpretability）** 旨在理解模型"为什么"做出某决策：

- **事后解释（Post-hoc）**：注意力可视化、归因方法（Integrated Gradients、SHAP）
- **探针实验（Probing）**：探测中间表征是否编码特定语义
- **机械可解释性（Mechanistic Interpretability）**：试图逆向工程模型的内部计算电路

Anthropic 提出的 **稀疏自编码器（Sparse Autoscopic, SAE）** 方法能从超级位置（Superposition）中分解出可解释的单义特征，是机械可解释性的重要进展。OpenAI 的"电路分析"揭示了 induction head、间接目标识别等机制。

机械可解释性的长远目标是为对齐提供"显微镜"，使我们能直接观察模型内部的目标、欺骗倾向，而非仅依赖外部行为。

## AI 安全治理框架

AI 安全已从技术问题扩展为社会-技术问题。主要治理框架：

- **国内**：《生成式人工智能服务管理暂行办法》《算法推荐管理规定》《深度合成管理规定》要求算法备案、内容标识、安全评估
- **欧盟**：《AI Act》按风险分级管理，对高风险 AI 设强制要求
- **美国**：NIST AI Risk Management Framework、总统行政令要求大模型安全测试
- **国际**：G7 广岛 AI 进程、联合国 AI 顾问机构推动全球协同治理

企业实践框架通常包含：安全评估、红队测试、模型卡（Model Card）、负责任发布原则、事故响应机制、第三方审计等环节。

## 总结

AI 安全与对齐是确保大模型可靠、可控、有益于人类的关键技术。从 RLHF 到 DPO，从 Constitutional AI 到机械可解释性，对齐技术正从"行为层面"深入到"机制层面"。面对越狱攻击、幻觉、奖励误设等挑战，单一技术无法解决所有问题——需要"技术 + 评估 + 治理"的多层防御体系。未来，随着模型能力逼近甚至超越人类水平，对齐研究的重要性将愈发凸显，是 AI 长期安全的基石。
