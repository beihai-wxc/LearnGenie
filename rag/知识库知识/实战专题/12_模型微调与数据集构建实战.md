# 模型微调与数据集构建实战

## 一、为何需要微调？

### 微调的核心价值

提示工程和RAG均**未改变模型的底层参数与知识边界**，而微调通过**定向调整模型参数**实现：

| 价值维度 | 说明 |
|---------|------|
| **领域适配** | 让通用模型掌握垂直领域知识（如法律条文解读、工业设备故障诊断） |
| **精度提升** | 针对细分任务，通过专项数据训练，降低模型"幻觉"与错误率 |
| **效率优化** | 微调后无需每次加载复杂提示或检索外部文档，响应速度更快 |
| **风格定制** | 让模型输出符合特定格式、语气或品牌风格 |

### 预训练 vs 微调

| 对比维度 | 预训练 | 微调 |
|---------|------------------|-------------------|
| **核心目标** | 学习通用知识（语言逻辑、常识） | 适配特定任务（医疗文本分类、数学解题） |
| **数据要求** | 大规模通用数据，无需标注 | 小规模任务相关数据，需标注 |
| **训练方式** | 自监督/无监督 | 有监督 |
| **参数更新** | 全量参数训练 | 部分/全量参数更新 |
| **资源消耗** | 极高（千亿级Token、数百张GPU） | 较低（万级Token、单张/几张GPU） |

### 微调的详细理论分析

**迁移学习为什么有效？——特征转移假设**

迁移学习的有效性基于一个核心假设：**源领域学到的特征对目标领域是有用的**。具体来说：

```
预训练模型学到的知识层次：
┌─────────────────────────────┐
│  高层特征：任务特定           │ ← 微调时主要修改
│  （情感极性、问答模式）        │
├─────────────────────────────┤
│  中层特征：语义组合           │ ← 微调时部分调整
│  （句法结构、逻辑关系）        │
├─────────────────────────────┤
│  低层特征：通用语言特征        │ ← 微调时通常保持
│  （词形、词性、基本语法）       │
└─────────────────────────────┘
```

**微调与特征提取的对比：**

| 方面 | 特征提取（Feature Extraction） | 微调（Fine-Tuning） |
|------|------------------------------|-------------------|
| 参数更新 | 仅训练新加的分类头 | 更新部分或全部参数 |
| 冻结策略 | 冻结预训练模型全部参数 | 可选择冻结/解冻不同层 |
| 效果 | 对相似任务效果好 | 对差异大的任务效果更好 |
| 过拟合风险 | 低 | 较高（需要更多正则化） |
| 训练时间 | 快 | 慢 |
| 适用场景 | 数据少、任务与预训练相似 | 数据较多、任务差异大 |

**灾难性遗忘问题：**

微调时如果学习率过大或训练太久，模型可能"忘记"预训练学到的通用知识，只在特定任务上表现好，泛化能力大幅下降。

```python
# 灾难性遗忘的表现：
# 微调前：模型能流畅生成各种话题的内容
# 微调后（过度）：模型只能生成特定领域的内容，其他任务表现急剧下降

# 解决方案：
# 1. 使用较小的学习率（比预训练小10-100倍）
# 2. 差异化学习率（低层小、高层大）
# 3. 渐进式解冻（先训练高层，再逐步解冻低层）
# 4. 使用LoRA/Adapter等参数高效方法（天然防止灾难性遗忘）
# 5. 正则化（L2、Dropout、Early Stopping）
# 6. 数据混合（微调数据中混入部分通用数据）
```

### 2.2 学习率设置策略

```python
# 微调LLM的学习率经验值：
# | 模型规模 | 推荐学习率 | 说明 |
# |---------|-----------|------|
# | < 1B    | 5e-5 ~ 1e-4 | 可以稍大 |
# | 1B-7B   | 1e-5 ~ 5e-5 | 常用范围 |
# | 7B-13B  | 5e-6 ~ 2e-5 | 偏小 |
# | > 13B   | 1e-6 ~ 1e-5 | 需要更小 |

# 差异化学习率：对不同层使用不同学习率
def get_differential_lr_groups(model, base_lr=2e-5, lr_scale=0.1):
    """低层使用更小的学习率，高层使用更大的学习率"""
    param_groups = []
    
    # 假设模型有N层，越靠前的层学习率越小
    for name, param in model.named_parameters():
        if not param.requires_grad:
            continue
        
        # 根据层号确定学习率缩放
        if 'embed' in name or 'layer.0' in name or 'layer.1' in name:
            param_groups.append({'params': param, 'lr': base_lr * lr_scale})
        elif 'layer.2' in name or 'layer.3' in name:
            param_groups.append({'params': param, 'lr': base_lr * lr_scale * 2})
        else:
            param_groups.append({'params': param, 'lr': base_lr})
    
    return param_groups

# 使用
optimizer = AdamW(get_differential_lr_groups(model, base_lr=2e-5))
```

### 2.3 渐进式解冻（Gradual Unfreezing）

```python
# 渐进式解冻：从高层开始训练，逐步解冻更多层
def gradual_unfreeze(model, current_epoch, unfreeze_schedule):
    """
    Args:
        unfreeze_schedule: {epoch: [要解冻的层名关键词]}
    """
    if current_epoch in unfreeze_schedule:
        keywords = unfreeze_schedule[current_epoch]
        for name, param in model.named_parameters():
            for kw in keywords:
                if kw in name:
                    param.requires_grad = True
                    print(f"  解冻: {name}")

# 示例：3阶段解冻
schedule = {
    0: ['classifier', 'lm_head'],           # 第0轮：只训练分类头
    2: ['layer.3', 'layer.4'],              # 第2轮：解冻最后2层
    4: ['layer.1', 'layer.2'],              # 第4轮：解冻更多层
}

for epoch in range(num_epochs):
    gradual_unfreeze(model, epoch, schedule)
    train_one_epoch(model, ...)
```

## 三、LoRA：低秩适应深入

### 3.1 LoRA的详细数学推导

LoRA的核心假设：**模型微调时的参数更新量 ΔW 是低秩的**。

```
原始权重矩阵：W ∈ R^(d×k)  （冻结不变）
更新量：ΔW = BA，其中 B ∈ R^(d×r), A ∈ R^(r×k), r << min(d,k)

前向传播：y = (W + ΔW)x = Wx + BAx = Wx + B(Ax)

为什么低秩分解有效？
1. 微调只需调整模型在特定子空间的行为
2. 预训练模型的权重已经足够好，更新量是"小而精"的
3. 类比：图像压缩（SVD分解），少量主成分就能保留主要信息

数学直觉：
- 原始参数量：d × k
- LoRA参数量：d × r + r × k = r(d + k)
- 当 r << min(d,k) 时，参数量大幅减少
- 例如：d=k=4096, r=16
  原始：4096×4096 = 16,777,216
  LoRA：16×(4096+4096) = 131,072 （仅0.78%）
```

**缩放因子的作用：**

```
实际输出：y = Wx + (α/r) × BAx

其中 α 是LoRA的缩放因子（lora_alpha）：
- α/r 控制LoRA更新相对于原始权重的比例
- α = r 时，缩放因子为1（默认）
- α = 2r 时，LoRA的影响力加倍
- 较大的 α/r → 更大的更新幅度，但可能不稳定
- 较小的 α/r → 更保守的更新，更稳定

选择建议：
- r=8 时，alpha=16（即 α/r=2）是常见选择
- r=16 时，alpha=32（即 α/r=2）也是常见选择
- 保持 α/r ≈ 2 是一个不错的起点
```

### 3.5 LoRA合并（Merge）的原理和实现

```python
# LoRA训练完成后，可以将LoRA权重合并回原始模型
# 合并后推理无额外开销

from peft import PeftModel

# 方法1：使用PEFT的合并功能
base_model = AutoModelForCausalLM.from_pretrained("base_model")
model = PeftModel.from_pretrained(base_model, "lora_checkpoint")
merged_model = model.merge_and_unload()  # 合并后LoRA权重融入原始权重
merged_model.save_pretrained("merged_model")

# 方法2：手动合并
# 合并公式：W_new = W + (alpha/r) * B @ A
def manual_merge_lora(model, lora_path):
    state_dict = torch.load(lora_path)
    for name, param in model.named_parameters():
        lora_A_key = f"{name}.lora_A.weight"
        lora_B_key = f"{name}.lora_B.weight"
        if lora_A_key in state_dict and lora_B_key in state_dict:
            A = state_dict[lora_A_key]  # (r, in_features)
            B = state_dict[lora_B_key]  # (out_features, r)
            scale = alpha / r  # 缩放因子
            param.data += scale * B @ A  # 合并

# 多LoRA融合（多个任务的LoRA权重融合）
# 方法1：线性插值
merged_weight = w1 * lora1_weight + w2 * lora2_weight  # w1+w2=1

# 方法2：TIES merging（更高级的融合方法）
# 1. 修剪：只保留每个LoRA中最大的k%参数
# 2. 符号选择：按多数投票决定每个参数的符号
# 3. 合并：对齐符号后取平均
```

## 四、QLoRA：量化LoRA详细讲解

### 4.1 4-bit量化的原理（NF4数据类型）

QLoRA的核心创新是**NF4（NormalFloat4）**数据类型，专为正态分布的权重设计。

```
传统4-bit量化（均匀量化）：
- 将FP32的值域均匀划分为16个区间
- 问题：权重通常服从正态分布，均匀量化浪费精度

NF4量化（非均匀量化）：
- 基于正态分布的分位数定义16个量化级别
- 每个区间包含相同概率的值
- 优势：在权重密集区域分配更多量化级别

NF4的量化级别（来自N(0,1)的分位数）：
[-1.0, -0.696, -0.476, -0.297, -0.147, 0, 0.147, 0.297, 
 0.476, 0.696, 1.0, ...]
 
量化过程：
1. 确定权重的绝对值最大值
2. 将权重归一化到[-1, 1]
3. 用NF4分位数近似每个权重值
4. 存储量化索引（4bit）+ 缩放因子

反量化：量化索引 × 缩放因子 → FP16/BF16 用于计算
```

### 4.2 双重量化

```python
# QLoRA的另一个创新：双重量化
# 量化后的缩放因子本身也可以被量化

# 普通量化：权重 → 4bit + 缩放因子(FP32)
# 双重量化：权重 → 4bit + 缩放因子(FP32) → 缩放因子量化为FP32 + 二级缩放因子

# 效果：每个参数额外节省约0.37bit的显存

# QLoRA的完整配置

    bnb_4bit_use_double_quant=True,        # 启用双重量化
)

# 加载模型
model = AutoModelForCausalLM.from_pretrained(

# 输出：trainable params: 13,107,200 || all params: 3,540,389,888 || trainable%: 0.37%
```

## 五、Adapter Tuning详细讲解

### 5.1 不同的Adapter设计

```python
import torch
import torch.nn as nn

# ===== Houlsby Adapter =====
# 在每个Transformer层的注意力和FFN之后都插入Adapter
class HoulsbyAdapter(nn.Module):
    def __init__(self, hidden_size, adapter_size=64):
        super().__init__()
        self.down_proj = nn.Linear(hidden_size, adapter_size)  # 降维
        self.up_proj = nn.Linear(adapter_size, hidden_size)    # 升维
        self.activation = nn.GELU()
        self.init_weights()
    
    def init_weights(self):
        # 初始化：下投影用小随机值，上投影用零
        # 这样初始时Adapter输出为0，不影响原始模型
        nn.init.normal_(self.down_proj.weight, std=1e-3)
        nn.init.zeros_(self.up_proj.weight)
        nn.init.zeros_(self.up_proj.bias)
    
    def forward(self, x):
        residual = x
        x = self.down_proj(x)
        x = self.activation(x)
        x = self.up_proj(x)
        return residual + x  # 残差连接

# ===== Pfeiffer Adapter =====
# 只在FFN之后插入Adapter（比Houlsby少一半）
# 结构相同，但插入位置不同

# ===== Adapter插入方式 =====
class TransformerLayerWithAdapter(nn.Module):
    def __init__(self, original_layer, adapter_size=64):
        super().__init__()
        self.original_layer = original_layer
        hidden_size = original_layer.hidden_size
        
        # Houlsby: 两个Adapter
        self.adapter_after_attn = HoulsbyAdapter(hidden_size, adapter_size)
        self.adapter_after_ffn = HoulsbyAdapter(hidden_size, adapter_size)
    
    def forward(self, hidden_states, ...):
        # 原始注意力
        attn_output = self.original_layer.attention(hidden_states)
        hidden_states = hidden_states + attn_output
        # Adapter
        hidden_states = self.adapter_after_attn(hidden_states)
        
        # 原始FFN
        ffn_output = self.original_layer.ffn(hidden_states)
        hidden_states = hidden_states + ffn_output
        # Adapter
        hidden_states = self.adapter_after_ffn(hidden_states)
        
        return hidden_states
```

### 5.2 Adapter的推理开销

```
Adapter的推理影响：

| Adapter类型 | 额外参数 | 推理延迟增加 | 说明 |
|------------|---------|-------------|------|
| Houlsby | 2×d×r per layer | ~5-10% | 每层2个Adapter |
| Pfeiffer | 1×d×r per layer | ~2-5% | 每层1个Adapter |
| LoRA | 2×d×r per target | ~0% (合并后) | 合并后无额外开销 |
| IA3 | 3×d per layer | ~0% | 仅向量缩放 |

关键对比：
- LoRA合并后零推理开销 → 部署首选
- Adapter始终有额外推理开销 → 不适合对延迟敏感的场景
- Adapter的优势：可以动态切换不同任务的Adapter（多任务服务）
```

```python
# 可训练参数极少：20 × hidden_size ≈ 20 × 4096 = 81,920

# Prompt Tuning的工作原理：
# 原始输入：[token1, token2, ..., tokenN]
# 加上Prompt：[virtual_1, virtual_2, ..., virtual_20, token1, token2, ..., tokenN]
# 只训练 virtual_1 ~ virtual_20 的嵌入向量
# 虚拟token不对应词表中的任何词，是完全可学习的

# ===== P-Tuning v2 =====
# 在每一层都添加可学习的prompt（深层prompt），效果比Prompt Tuning好

from peft import PrefixTuningConfig

config = PrefixTuningConfig(
    task_type="CAUSAL_LM",
    num_virtual_tokens=20,
    prefix_projection=True,       # 使用投影层
    projection_dim=512,           # 投影维度
)

# P-Tuning v2 vs Prompt Tuning：
# | 方面 | Prompt Tuning | P-Tuning v2 |
# |------|--------------|-------------|
# | 可学习参数位置 | 仅输入层 | 每一层 |
# | 效果 | 小模型效果差 | 全面优于Prompt Tuning |
# | 参数量 | 更少 | 更多 |
# | 适合模型规模 | >10B | 所有规模 |

# 经验：
# Prompt Tuning只适合大模型（>10B），小模型效果很差
# P-Tuning v2在各种规模模型上都有效
# 对于LLM微调，LoRA仍是首选
```

## 七、IA3详细讲解

```python
# IA3: Injected Attention and Adapted Activations
# 通过学习向量对Key、Value和FFN输出进行缩放

# 核心公式：
# 注意力中：K' = l_k ⊙ K, V' = l_v ⊙ V  （⊙ 逐元素乘）
# FFN中：FFN' = l_ff ⊙ FFN_output
# 其中 l_k, l_v, l_ff 是可学习的向量（不是矩阵！）

# 参数量对比（以d=4096为例）：
# LoRA r=16: 2 × 4096 × 16 = 131,072 per target module
# IA3: 4096 per vector × 3 = 12,288 per layer
# IA3的参数量约为LoRA的1/10

from peft import IA3Config, get_peft_model

config = IA3Config(
    task_type="CAUSAL_LM",
    target_modules=["k_proj", "v_proj", "down_proj"],  # 对K, V, FFN缩放
    feedforward_modules=["down_proj"],  # 指定哪些是FFN模块
)

model = get_peft_model(model, config)
model.print_trainable_parameters()

# IA3优势：
# 1. 参数极少（LoRA的1/10）
# 2. 推理时可以合并（向量缩放融入权重）
# 3. 适合极端资源受限场景

# IA3劣势：
# 1. 表达能力不如LoRA
# 2. 在复杂任务上效果可能不如LoRA
```

```python
import re
import json
from collections import Counter

def clean_quality_control(data_list):
    """数据清洗和质量控制Pipeline"""
    cleaned = []
    stats = {"total": len(data_list), "removed": 0, "reasons": Counter()}
    
    for item in data_list:
        # 1. 去除空数据
        if not item.get('instruction') or not item.get('output'):
            stats["removed"] += 1
            stats["reasons"]["empty"] += 1
            continue
        
        # 2. 去除过短/过长的数据
        output_len = len(item['output'])
        if output_len < 10:
            stats["removed"] += 1
            stats["reasons"]["too_short"] += 1
            continue
        if output_len > 4096:
            stats["removed"] += 1
            stats["reasons"]["too_long"] += 1
            continue
        
        # 3. 去除重复数据
        # (在外部使用set或minhash去重)
        
        # 4. 去除低质量数据（包含大量特殊字符等）
        special_char_ratio = len(re.findall(r'[^\w\s\u4e00-\u9fff.,!?;:，。！？；：]', 
                                            item['output'])) / max(output_len, 1)
        if special_char_ratio > 0.3:
            stats["removed"] += 1
            stats["reasons"]["special_chars"] += 1
            continue
        
        # 5. 去除模板化回答
        template_phrases = ["我无法回答", "作为AI", "I cannot", "As an AI"]
        if any(phrase in item['output'] for phrase in template_phrases):
            stats["removed"] += 1
            stats["reasons"]["template"] += 1
            continue
        
        cleaned.append(item)
    
    print(f"清洗结果: {stats['total']} → {len(cleaned)} (移除{stats['removed']}条)")
    print(f"移除原因: {dict(stats['reasons'])}")
    return cleaned

# 去重（MinHash LSH）
def deduplicate_minhash(texts, num_perm=128, threshold=0.7):
    """使用MinHash进行近似去重"""
    from datasketch import MinHash, MinHashLSH
    
    lsh = MinHashLSH(threshold=threshold, num_perm=num_perm)
    unique_texts = []
    
    for i, text in enumerate(texts):
        mh = MinHash(num_perm=num_perm)
        for word in text.split():
            mh.update(word.encode('utf-8'))
        
        if not lsh.query(mh):  # 没有相似的
            lsh.insert(str(i), mh)
            unique_texts.append(text)
    
    return unique_texts
```

```python
# ===== 自动评估 =====

# 1. 困惑度（Perplexity）— 评估语言模型质量
def compute_perplexity(model, tokenizer, texts, device='cuda'):
    import math
    model.eval()
    total_loss = 0
    total_tokens = 0
    for text in texts:
        inputs = tokenizer(text, return_tensors='pt').to(device)
        with torch.no_grad():
            outputs = model(**inputs, labels=inputs['input_ids'])
            total_loss += outputs.loss.item() * inputs['input_ids'].size(1)
            total_tokens += inputs['input_ids'].size(1)
    return math.exp(total_loss / total_tokens)
```

```python
    load_in_4bit=True,    # 4-bit量化
)

# 添加LoRA适配器
model = FastLanguageModel.get_peft_model(
    model,
    r=16,
    lora_alpha=32,
    lora_dropout=0.05,
    target_modules=["q_proj", "k_proj", "v_proj", "o_proj",
                    "gate_proj", "up_proj", "down_proj"],
)

# 训练（与标准HuggingFace Trainer相同）
from trl import SFTTrainer
from transformers import TrainingArguments

trainer = SFTTrainer(
    model=model,
    train_dataset=dataset,
    args=TrainingArguments(
        per_device_train_batch_size=4,
        gradient_accumulation_steps=8,
        num_train_epochs=3,
        learning_rate=2e-5,
        output_dir="outputs",
        bf16=True,
    ),
)
trainer.train()

# Unsloth优势：
# 1. 训练速度提升2-5倍
# 2. 显存减少约60%
# 3. 无需手动配置量化
# 4. 兼容HuggingFace生态系统
```

## 十四、模型训练状态判断

| 模型状态 | 损失表现 | 解决策略 |
|---------|---------|---------|
| **训练失败** | 训练损失不变甚至上升 | ①检查数据格式 ②调整学习率 ③检查模型配置 |
| **欠拟合** | 两者均下降但仍较高 | ①增加训练轮次 ②扩大数据集 ③增大LoRA的秩 |
| **过拟合** | 训练损失下降，验证损失上升 | ①减少训练轮次 ②增加数据多样性 ③增大dropout率 ④减小批量大小 |
| **灾难性遗忘** | 微调任务好，其他任务差 | ①降低学习率 ②混入通用数据 ③使用LoRA而非全参 |

## 十五、常见微调问题的排查

```
问题排查清单：

1. Loss不下降
   → 检查数据格式是否正确（instruction/output是否对齐）
   → 检查tokenizer的max_length是否足够
   → 检查学习率是否太小（试试2e-5）
   → 检查是否所有参数都被冻结了

2. Loss为NaN
   → 降低学习率
   → 检查数据是否包含异常值
   → 使用bf16而非fp16
   → 检查label是否正确对齐

3. 生成重复内容
   → 增加数据多样性
   → 减小学习率
   → 增加lora_dropout
   → 减少训练轮次

4. 输出格式不对
   → 在instruction中明确指定输出格式
   → 增加格式正确的训练样本
   → 使用system prompt约束格式

5. 显存不足（OOM）
   → 使用QLoRA替代LoRA
   → 减小batch_size + 增大gradient_accumulation_steps
   → 减小max_seq_length
   → 使用Unsloth加速

6. 中文效果差
   → 确保使用中文预训练模型
   → 增加中文训练数据比例
   → 检查tokenizer是否支持中文
```

---

> **核心总结**：微调的核心步骤是**"选模型→选方法（LoRA）→准备数据→训练→评估→部署"**。LoRA是资源受限场景的首选，QLoRA进一步降低显存需求。数据质量比数量更重要，至少需要1000+条优质数据。选择微调方法时考虑资源、任务复杂度和推理需求：LoRA适合通用场景，QLoRA适合消费级GPU，Adapter适合多任务切换，全参微调适合数据充足的场景。
